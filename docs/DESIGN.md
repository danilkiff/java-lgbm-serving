# Дизайн: цель, метод, альтернативы, результат

Фундаментальное требование: код причины на отклонение - точная атрибуция того же
предиктора, что принял решение, а не post-hoc приближение. Оно форсирует разом
два свойства:

- точная атрибуция - SHAP contributions из того же предиктора, что скорит вход;
- численный паритет инференса на JVM с эталоном на Python - он и доказывает "тот
  же предиктор".

Остальной дизайн выводится отсюда.

## Метод

FFM грузит через `dlopen` ровно тот файл `lib_lightgbm`, что исполнял обучение:
`native/` ставит колесо lightgbm по фиксированным хешам, то же колесо с PyPI
стоит у обучения, значит байты библиотеки те же. JVM и Python исполняют один
нативный предиктор, и паритет ограничен только платформой.

Оговорка о платформе точная: колесо одной версии несёт разные бинарники под
разные платформы, поэтому битовое совпадение гарантировано, когда эталоны
посчитаны на той же платформе, что и проверка. Эталоны из релиза собираются на
linux-amd64, и на darwin-arm64 SHAP расходится в последних битах (`6.7e-16` при
допуске `1e-6`), а raw margin совпадает до бита. Входы при этом у всех одни:
`holdout.csv` берётся из архива, а не пересчитывается - его собственная
воспроизводимость упирается в libm платформы (numpy `gamma`).

Что проверяется и где:

- воспроизводит оценку - отклонение raw margin и число смен решения,
`ParityTest.rawMarginMatchesPython`;
- нативный SHAP корректен - поэлементное отклонение от Python
`predict(pred_contrib=True)`, `ParityTest.shapContributionsMatchPython`;
- SHAP внутренне согласован - инвариант sum(contrib) = raw margin, там же;
- код причины устойчив - порядок топ-K признаков совпадает с эталоном, там же;
- версия библиотеки та же, что обучала - `ParityTest.nativeVersionMatchesTrainingVersion`;
- переносимо между платформами и языками - дамп на каждой стороне, затем
`DumpMain compare`;
- конкуренция корректна - 64 потока по 500 предсказаний против однопоточного
эталона, `PoolTest.concurrentPredictionsMatchSingleThreaded`;
- стоимость SHAP не попадает на горячий путь - `HotPathIsolationTest`;
- задержка и пропускная способность - бенчмарки JMH в `src/jmh`.

## Выбор: способ вызова LightGBM из JVM

> Битовый паритет держится на том, что вызывается тот же бинарник, а не та же
> версия.

- Panama FFM: `SymbolLookup.libraryLookup` открывает конкретный файл, поэтому
свойство сохраняется дословно; нативного кода нет, кросс-компиляции нет. Выбрано;
- рукописный JNI: численно то же самое, но добавляет C-шим и сборку под каждую
платформу, то есть вторую поверхность отладки без выигрыша в точности;
- `lightgbm4j` поверх SWIG-биндинга: `C_API_PREDICT_CONTRIB` поддержан, старт
быстрый, но нативная библиотека своей сборки лежит внутри jar - паритет
становится кросс-сборочным;
- ONNX Runtime: SHAP-оператора нет, а конвертация модели добавила бы вторую
поверхность расхождения;
- чистый Java-инференс: реализует предиктор заново и вносит своё
float-расхождение.

Прототипы C-ABI описаны вручную (шесть функций), а не сгенерированы jextract:
`c_api.h` тянет C++ и Arrow, генератор здесь дал бы тысячи строк ради шести
сигнатур.

## Выбор: примитивы конкуренции

Общий хэндл Booster сериализует предсказание; кроме того, C API LightGBM
3.0.0-3.1.1 ключевал буфер по `omp_get_thread_num()`, который для чужих потоков
возвращает 0 ([#3751](https://github.com/microsoft/LightGBM/issues/3751)).
Минимальная безопасная версия - 3.2.0
([#3771](https://github.com/microsoft/LightGBM/pull/3771)); здесь зафиксирована
4.6.0.

Выбран пул независимых хэндлов, по одному на вызов, с `num_threads=1` на
предсказание: один нативный поток заодно убирает недетерминизм float-редукции
OpenMP, а параллелизм держится на уровне JVM. Цена - копия модели в памяти на
хэндл.

Воркеры explain работают на платформенных потоках: нативный downcall занимает
несущий поток целиком, поэтому виртуальные ничего не дали бы, а конкурентность
и так ограничена размером пула.

## Особенности JVM

- буферы обмена с нативной стороной живут в арене хэндла и переиспользуются,
поэтому скоринг не аллоцирует (0.12 Б на вызов по `-prof gc`);
- арена хэндла shared, а не confined: хэндл из пула по очереди берут разные
потоки, а confined-арена запрещает доступ всем, кроме создавшего;
- `Linker.Option.critical` не применяется: опция предназначена для функций с
крайне коротким временем работы, а предсказание идёт десятки микросекунд;
- FFM - restricted API: с JDK 24 вызов без `--enable-native-access` печатает
предупреждение, в будущих выпусках станет ошибкой, поэтому флаг задан для
запуска, тестов и бенчмарков;
- замеры задержки предваряются прогревом: без него измерялась бы работа
интерпретатора и компиляция, а не установившееся состояние.

## Результат

Доказано, трудная часть: код причины точен и доказуемо выводится из инференса,
устойчивость порядка топ-K проверяется в CI. Это суть объяснимости решений.

Доказано дополнительно, чего не мог показать один язык: граница языка не вносит
численного расхождения. Дампы Java и Go на одной модели и одном входе совпадают
до бита, а быстродействие различается в пределах единиц процентов - обе
реализации упираются в один нативный предиктор.

Построено: конвейер decline-explain - SHAP вне горячего пути, только для
отклонений, асинхронно, в одном процессе за интерфейсами `Queue` и `Store`
(`pipeline` плюс `cli/ScorerMain`).

Контракт объяснений - best-effort с видимой потерей: ограниченная очередь может
отбросить событие, и тогда вызывающий узнаёт это сразу (`explain_queued=false` в
ответе скоринга), оператор - из метрик (`queue_dropped`) и dead-letter.
Согласованность объяснения с решением обеспечена по построению - margin и
contributions считает один пул из одних байт. В причины отклонения отбираются
только contributions, толкавшие к нему; факторы в пользу одобрения причиной
отклонения не бывают. Строгая гарантия "объяснение на каждое отклонение"
требует durable-очереди с подтверждением до ответа - адаптер за тем же
интерфейсом `Queue`, вне охвата вместе с сетевым развёртыванием.

Вне охвата: обучение модели и валидация её качества (репозиторий эталонов),
утверждённая таксономия adverse-action кодов и текст уведомления (механизм есть -
`reasoncode.Catalog` плюс `codes.json`, утверждённого набора кодов нет),
развёрнутый сетевой сервис, нагрузочный тест против SLA.
